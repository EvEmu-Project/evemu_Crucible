# NPC market sell prices — 100% of reference item value

**Date:** 16 November 2026. **Scope:** EVEmu Crucible 1.6.5.

## Confirmed inflation sources

1. `tools/evedbtool/command_seed.go`: standard AND rare
   regional NPC sell-order SQL used `invTypes.basePrice / station.security`.
   A station at security 0.5 therefore charged 200% of base value;
   at 0.1 it charged 1,000%.
2. `src/eve-server/market/MarketBotMgr.cpp`: Trader Joe NPC
   `CalculateSellPrice` multiplied `basePrice` by a random 1.0–1.3
   (up to 130%). The bot's **buy** offers are unrelated and unchanged;
   modifying outstanding buy prices would require escrow recalculation.
3. The legacy regional `sql/seed_and_clean/seed_market.sql` used the
   same security division (including a rare-item path).
   The legacy single-station seeder already used `basePrice`, but had
   an unscoped `UPDATE mktOrders SET price=100 WHERE price=0` that
   could modify unrelated existing player orders.

All **new NPC sell orders** generated by the modified seeders and Trader
Joe now use 100% of the static item reference price, with **no extra
security-based or random sell markup**.

**Definition of "100%":** `invTypes.basePrice`. It is not the current
player-driven regional weighted average or live EVE market value.
`mktOrders.price` is `DECIMAL(16,2)`, so reference prices are
rounded to two decimals with a minimum of **0.01 ISK**. For a type
whose base price is NULL, zero or negative, a true percentage cannot
be calculated: the server retains the existing explicit **100 ISK
fallback** rather than making the item free.

## Existing overpriced NPC orders (one-time SQL repair)

The code change does not retroactively rewrite market orders already
saved in MariaDB. Use the included script:

`sql/diagnostics/2026-11-16-normalize-npc-sell-orders-100-percent.sql`

This script performs two read-only **PREVIEW** queries, a scoped
`START TRANSACTION` / `UPDATE` / `COMMIT`, and a final verification query.

It updates **only sell orders** (`bid=0`) in real stations where
`ownerID` matches:
- the station's `staStations.corporationID` (regular NPC seeded orders),
- the station's `staStations.stationID` (legacy single-station seeding),
- or the hardcoded NPC bot `1000125` (Trader Joe/CONCORD).

It leaves player and other corporation orders, all buy orders, item
quantities, escrow, historical transactions, character money and
`invTypes.basePrice` unchanged. It neither deletes nor reseeds orders.
It works across **all configured and unconfigured regions**, rather
than applying only to the regions in `seed-regions`.

**Deployment steps:**
1. Stop the EVEmu server and market bot, and take a full MariaDB backup.
2. Run the two PREVIEW queries and confirm the owner IDs correspond to
   your NPC sellers. Save the reported number and examples of markups.
3. Execute the transaction and check
   `npc_sell_order_prices_updated`; preserve the backup for rollback.
4. The last SELECT should report
   `remaining_mismatched_npc_sells = 0`.
5. Restart the EVEmu server to invalidate its cached market order results.
   Test an overpriced item in a 0.1–0.5 security station and compare the
   exact order price with `invTypes.basePrice`.

An alternative is `evedbtool seed -force`, but this replaces the
eligible NPC sell orders **only within seed-regions**, changes their
quantities/issued timestamps and may not reach every existing order.
For this request, the in-place NPC-only SQL repair is preferred.
